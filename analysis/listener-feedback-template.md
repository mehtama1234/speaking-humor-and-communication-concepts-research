# Listener Feedback Template

Simple external-feedback template for getting useful speaking feedback from a
 friend, peer, teammate, or coach.

Date: August 10, 2026.

## Purpose

The speaking atlas now supports:

- self-diagnosis
- focused practice
- sample recording
- self-scoring
- weekly review

What it still needed was a better way to use outside eyes and ears.

Most learners ask for feedback in a way that produces weak answers:

- “How did that sound?”
- “Was that okay?”
- “Anything I should improve?”

Those questions usually generate vague reassurance instead of useful signal.

This template gives the repo a lightweight external-feedback layer so the
learner can gather sharper observations without needing a formal coach.

If you already know the listener’s comment but not the exact replacement move,
pair this file with `analysis/transcript-backed-concrete-speaking-approaches.md`
so the feedback points to a named behavior, not just a vague weakness.

## When to use this

Use this after:

- a baseline recording
- a week-one retest
- a practice talk, work update, or short live presentation

If you are evaluating a multi-turn scenario or back-and-forth exchange, also
use:

- `analysis/roleplay-feedback-scorecard.md`
- `analysis/partner-roleplay-facilitator-guide.md`

If you want the listener to compare your version against a stronger real-world
adaptation instead of commenting in the abstract, also use:

- `analysis/real-world-speaking-application-examples.md`

## How to use it

1. Send or show one short speaking sample.
2. Ask the listener to answer only the questions below.
3. Tell them to choose the clearest observation, not to fix everything.
4. Use their feedback alongside `analysis/speaking-progress-scorecard.md`, not
   instead of it.
5. After reviewing the feedback, choose one exact move from
   `analysis/transcript-backed-concrete-speaking-approaches.md` for the next
   rep.

## Instructions for the listener

Please answer briefly and concretely.

Do not try to be nice by smoothing everything over.

Focus on:

- what was easiest to understand
- what weakened trust or attention
- the one thing that would most improve the next version

## Core listener questions

### 1. What was the main point you heard?

Why this matters:

- if the listener cannot answer this cleanly, structure is probably weak

### 2. At what moment did the speaker sound strongest?

Why this matters:

- this shows what behavior should be repeated, not only what should be fixed

### 3. At what moment did the speaker sound weakest or least clear?

Why this matters:

- this often reveals the real failure point faster than abstract feedback does

### 4. Did the speaker sound rushed, calm, or somewhere in between?

Why this matters:

- many learners misread their own pace and pressure leakage

### 5. Did the answer feel structured, or did it wander before the point?

Why this matters:

- this helps separate clarity problems from confidence problems

### 6. Did the speaker sound credible and useful?

Why this matters:

- especially important for workplace updates, recommendations, and high-stakes
  answers

### 7. If there was humor or playfulness, did it feel natural or forced?

Why this matters:

- learners often cannot judge this well in real time

### 8. What is the one change that would improve the next version most?

Why this matters:

- this keeps feedback actionable instead of overloaded

## Fast listener form

Copy and send:

```text
Please answer these briefly after watching/listening:

1. What was the main point you heard?
2. Where did I sound strongest?
3. Where did I sound weakest or least clear?
4. Did I sound rushed, calm, or mixed?
5. Did the answer feel structured or wandering?
6. Did I sound credible and useful?
7. If there was humor, did it feel natural or forced?
8. What is the one change that would improve the next version most?
```

## Best ways to use the feedback

If the listener cannot state the main point:

- return to `concepts/structure-as-leverage.md`
- start with `Approach 5`, `Approach 6`, or `Approach 14` in
  `analysis/transcript-backed-concrete-speaking-approaches.md`

If the listener says the answer wandered:

- return to `concepts/audience-first-communication.md`
- start with `Approach 1` or `Approach 6` in
  `analysis/transcript-backed-concrete-speaking-approaches.md`

If the listener says you sounded rushed:

- return to `concepts/pause-as-strength.md`
- start with `Approach 2`, `Approach 3`, or `Approach 21` in
  `analysis/transcript-backed-concrete-speaking-approaches.md`

If the listener says you sounded weak or tentative:

- return to `concepts/executive-presence.md`
- start with `Approach 7`, `Approach 12`, or `Approach 20` in
  `analysis/transcript-backed-concrete-speaking-approaches.md`

If the listener says the humor felt forced:

- return to `concepts/humor-timing-and-collaborative-play.md`
- start with `Approach 11` or `Approach 17` in
  `analysis/transcript-backed-concrete-speaking-approaches.md`

If the listener struggles to explain what the stronger version would sound
like:

- compare your rep against `analysis/real-world-speaking-application-examples.md`
- then ask the listener which version sounds more usable in a real room and why

## What not to ask for

Avoid asking:

- “Did you like it?”
- “Was that good?”
- “Can you just give me general feedback?”

These produce too little signal and too much politeness.
