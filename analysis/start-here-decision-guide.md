# Start-Here Decision Guide

Fast route selection for readers entering the speaking atlas cold.

Date: August 10, 2026.

## Purpose

The atlas now has:

- diagnosis
- a practice operating system
- quickstarts
- pathways
- weekly sprints
- month-one structure
- pre-flight checklists

What it still needed was a clean decision layer for a first-time reader:

- which artifact should I open first based on what I need right now?
- if I need examples, what kind of examples should I study first?

This file answers that directly.

## Use this if

Use this guide if:

- the repo looks rich but you do not know where to begin
- you need improvement help for a specific situation
- you want the fastest route instead of exploring the whole site first

## Choose your entry point by need

### If you are brand new and want the fastest useful start

Open:

- `analysis/first-session-quickstart.md`
- `analysis/speaking-practice-operating-system.md`

Why:

- it gets you from zero to one diagnosis, one baseline sample, and one next
  step in the same sitting
- it also tells you which layer to use next once the first sitting is done

### If you know the real-life situation, but not the skill problem underneath it

Open:

- `analysis/context-based-speaking-routes.md`

Why:

- it routes by meetings, interviews, presentations, social conversation,
  humor, and skeptical rooms

### If you already know the main failure mode

Open:

- `analysis/learner-pathways.md`

Why:

- it routes directly by freezing, rambling, flat delivery, social hesitation,
  hard questions, business communication, and skeptical rooms

### If you want concrete things to do this week

Open:

- `analysis/transcript-backed-concrete-speaking-approaches.md`
- `analysis/focused-improvement-actions.md`
- `analysis/weekly-plans-by-learner-type.md`
- `analysis/speaking-pattern-practice-recipes.md`
- `analysis/speaking-common-mistakes-and-fixes.md`
- or `analysis/weekly-practice-sprints.md`

Why:

- these are the fastest bridges from understanding to repetition
- the transcript-backed approaches file gives you named moves drawn from the
  current corpus before you build a full weekly loop

### If you want a full week planned for your kind of learner

Open:

- `analysis/weekly-plans-by-learner-type.md`

Why:

- it gives you a seven-day plan for common learner types like work-focused,
  pressure-heavy, socially stiff, humor-focused, presentation-focused, and
  multilingual learners

### If you want one ready-made mini-stack for a specific problem

Open:

- `analysis/speaking-pattern-practice-recipes.md`

Why:

- it gives you one practical recipe combining the speaker model, the
  before-and-after example, the short drill, and the live challenge

### If you want to see what using the stack looks like across a few days

Open:

- `analysis/speaking-practice-case-studies.md`

Why:

- it shows realistic learner-style examples of someone using the files,
  running the reps, and then trying the move in a real conversation, meeting,
  interview, or talk

### If your main problem is the second turn after your first answer

Open:

- `analysis/speaking-roleplay-packs.md`
- `analysis/roleplay-feedback-scorecard.md`

Why:

- these help you practice what happens after the first answer, when pushback,
  sharper follow-ups, or social pressure test whether the move actually holds

### If you mostly need to spot what you keep doing wrong

Open:

- `analysis/speaking-common-mistakes-and-fixes.md`

Why:

- it helps you identify the visible behavior to replace before you choose a
  bigger weekly route

### If you know the problem but not what to say in the moment

Open:

- `analysis/live-speaking-phrase-bank.md`

Why:

- it gives you adaptable sentence shapes for pressure, work, social, and
  hard-question moments without forcing full scripts

### If you want concrete before-and-after situations

Open:

- `analysis/worked-speaking-situation-examples.md`

Why:

- it shows weak versions, stronger replacements, and how to adapt them in real
  meetings, answers, conversations, and presentations

### If you want named speaker examples tied to exact real situations

Open:

- `analysis/speaking-move-deployment-examples.md`

Why:

- it shows an actual speaker or source anchor, the move being used, a weak
  real-life version, a stronger real-life version, and the kind of room where
  you should try the move next

### If you want to study actual people using the move well

Open:

- `analysis/real-speaker-exemplars.md`

Why:

- it extracts usable patterns from named speakers so you can borrow the move
  without copying their personality

### If you want the speaker, the room, and the exact adaptation together

Open:

- `analysis/real-world-speaking-application-examples.md`

Why:

- it shows an actual person using the move, the real-life room where the same
  move belongs, a weak version, and a stronger version you could actually use

### If you need something closer to the real situation

Open:

- `analysis/real-life-speaking-simulations.md`

Why:

- it turns practice into realistic meeting, interview, presentation, social,
  and objection-handling rehearsal

### If you want to watch something strong before practicing

Open:

- `analysis/watch-before-you-practice-guide.md`

Why:

- it gives a transcript-backed watch route and then tells you exactly what to
  practice next

### If you want to know why a drill is worth trusting

Open:

- `analysis/evidence-backed-drill-map.md`

Why:

- it ties the core drills back to specific transcript-backed evidence moments
  and visible behavior targets

### If you have a real speaking event soon

Open:

- `analysis/speaking-preflight-checklists.md`

Why:

- it helps in the last 5 to 20 minutes before a meeting, interview, talk, or
  social moment

### If you practiced already but are not improving

Open:

- `analysis/stalled-progress-troubleshooting-guide.md`

Why:

- it helps debug wrong diagnosis, overload, weak repetition, hard prompts, and
  missing feedback

### If you want a structured first month

Open:

- `analysis/month-one-speaking-training-plan.md`
- `analysis/30-day-speaking-challenge.md`

Why:

- it sequences diagnosis, sprints, retests, feedback, and review into a
  stronger month-one block
- the challenge version gives you a simpler week-by-week path with live
  assignments

### If your main goal is better work communication

Open:

- `analysis/business-communication-curriculum.md`

Why:

- it compresses the repo into a direct work-facing route for updates,
  recommendations, pitches, and stakeholder communication

## Four common reader types

### Reader type 1: “I just opened this repo.”

Start with:

- `analysis/first-session-quickstart.md`

Then move to:

- `analysis/speaking-diagnosis-guide.md`
- `analysis/speaking-sample-prompt-bank.md`

### Reader type 2: “I have an event this week.”

Start with:

- `analysis/speaking-preflight-checklists.md`

Then move to:

- `analysis/context-based-speaking-routes.md`
- `analysis/worked-speaking-situation-examples.md`

### Reader type 3: “I know my weakness and want reps.”

Start with:

- `analysis/learner-pathways.md`
- `analysis/weekly-practice-sprints.md`

Then layer in one of:

- `analysis/worked-speaking-situation-examples.md`
- `analysis/speaking-move-deployment-examples.md`
- `analysis/real-speaker-exemplars.md`
- `analysis/real-world-speaking-application-examples.md`
- `analysis/30-day-speaking-challenge.md`

depending on whether you need realistic situations or source-backed speaker
models or a more exact real-world adaptation

### Reader type 4: “I already tried and nothing changed.”

Start with:

- `analysis/stalled-progress-troubleshooting-guide.md`

Then revisit:

- `analysis/speaking-diagnosis-guide.md`
- `analysis/time-budget-practice-guide.md`

## Minimum-friction recommendation

If unsure, use this order:

1. `analysis/first-session-quickstart.md`
2. `analysis/speaking-diagnosis-guide.md`
3. `analysis/focused-improvement-actions.md`
4. `analysis/worked-speaking-situation-examples.md`
5. `analysis/real-world-speaking-application-examples.md`
6. `analysis/weekly-practice-sprints.md`

This is the safest general route for a new learner because it prevents
over-reading before a baseline and before actual reps.
